ETF Trend Prediction — Data Preparation Report

European ETFs: IEUR, FEZ, EUFN

1. Overview

This report documents the data preparation pipeline for our ETF trend prediction project, which adapts the methodology of Sagaceta-Mejía et al. (2024) to three European ETFs:

Ticker Fund Focus
IEUR iShares Core MSCI Europe ETF Broad European market
FEZ SPDR EURO STOXX 50 ETF Eurozone large-cap
EUFN iShares MSCI Europe Financials ETF European financials
IVV iShares Core S&P 500 ETF Developed benchmark

Data spans 2010-01-01 → 2026-04-30, extending the paper’s original pre-pandemic window to include recent market conditions including the COVID-19 period and subsequent recovery.

4.1 Technical Indicators

The Pandas TA library (v0.4.x) expands the 6 base OHLCV features to ~250 daily features across 10 categories. Sparse columns with more than 95% NaN values (e.g. ZIGZAG) are automatically removed before cleaning.

Look-ahead check. Every indicator is tested for causality by recomputing it on data truncated at day t and checking that none of its values up to day t change. With default settings, five pandas-ta indicators fail this test and are dropped: DPO (centred, shifts the close backwards), the Ichimoku chikou span ICS_26 (the close 26 days in the future), the TOS_STDEVALL regression bands (fitted on the whole sample), VHM (normalised with future data) and ZIGZAG (pivots confirmed only by later prices). Ichimoku’s forward span projections, dated after the last trading day, are also discarded. The check runs in the unit tests, so a library upgrade that introduces a new look-ahead indicator fails the build.

The raw Adj Close column is excluded from the features as well: Yahoo back-adjusts it with dividends paid after each day, so its historical values are revised whenever a new dividend arrives. Indicators are computed on the unadjusted Close.

4.2 Classification Target Γ(t)

Following the paper (Section 2.4):

\[\Gamma(t) = \begin{cases} +1 & \text{if } \text{Open}(t) - \text{Open}(t-1) > 0 \\ -1 & \text{otherwise} \end{cases}\]

5. Preprocessing

5.1 Normalisation

Each feature is min-max scaled to [0, 1], but causally: the min and max are those observed up to that day, not over the whole sample:

\[\hat{x}_t = \frac{x_t - \min_{s \le t} x_s}{\max_{s \le t} x_s - \min_{s \le t} x_s}\]

The paper scales with full-sample statistics, which leaks the future range of every feature into earlier rows once the data is split into walk-forward folds. Expanding-window scaling avoids this while keeping a single processed dataset that every fold can share.

5.2 Cleaning

Two-stage cleaning is applied:

  1. Sparse column removal — columns with >95% NaN (e.g. ZIGZAG indicator) are dropped entirely before row-level cleaning.
  2. Forward-fill — remaining NaN values from indicator warm-up periods are forward-filled, then any residual NaN rows are dropped.

for ticker, df in datasets.items():
    n_nan = df.isna().sum().sum()

7. Handoff Contract

The modeling team receives:

  • Location: data/processed/{TICKER}_processed.parquet
  • Schema: DatetimeIndex + ~250 numeric feature columns + "Gamma" target column
  • Values: All features scaled to [0, 1]; Gamma ∈ {+1, -1}; zero NaNs
  • Causality: every feature value at day t uses only data up to day t, so the frame can be split into walk-forward folds as is
  • Note: IEUR has fewer rows (~2400) than FEZ/EUFN/IVV (~3500) due to data availability starting June 2014
Code 
# Verify handoff contract
for ticker, df in datasets.items():
    assert df.isna().sum().sum() == 0, f"{ticker} has NaNs!"
    assert "Gamma" in df.columns
    assert df["Gamma"].isin([1, -1]).all()
    feature_cols = [c for c in df.columns if c != "Gamma"]
    assert df[feature_cols].min().min() >= -0.01
    print(f"{ticker} ✓  shape={df.shape}")
